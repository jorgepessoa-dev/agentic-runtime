## Distribution modes

1. **Source repository dependency:** dependency declarations and the lockfile identify packages but do not contain their source or wheels. Users install upstream packages separately. Keep this attribution table with the source release.
2. **Python dependency wheel installed by an end user:** the package installer downloads the Psycopg wheel from its upstream index as a separate distribution. This project does not mirror, modify, or redistribute that wheel; upstream's wheel must carry the licenses/notices required for its own contents. If a downstream user redistributes it, that distributor takes on the applicable component and LGPL obligations.
3. **Project-distributed wheel:** none is produced today (`tool.uv.package = false`). A future project wheel that only declares dependencies still installs those dependencies separately; it should carry the project license and this notice. If it embeds third-party code, include the relevant full license/NOTICE files and satisfy that component's terms.
4. **Container/image:** none is distributed today. An image is a redistribution of its OS and Python packages. Include or preserve their license files and notices, record exact package versions, and review LGPL obligations for the actual dynamic/static linkage and image update/relink model.
5. **Bundled executable:** none is distributed today. A future bundle containing Psycopg or its libraries needs a component inventory, required license/NOTICE texts and (for LGPL components) a reviewed corresponding-source/relinking approach. The owner should obtain legal review of the concrete packaging format before release.

## Psycopg installation profiles

Development and quickstart use the upstream `psycopg[binary]` extra for broad platform coverage and no compiler/libpq setup. Production deployments use the pure `psycopg` package with the operating system's `libpq` and TLS libraries so the system package security-update process supplies library fixes. The performance-optimized `psycopg[c]` build remains an optional operator choice and requires a compiler and PostgreSQL development headers. This repository does not redistribute dependency wheels. A future project-distributed image or executable needs a fresh component-level licensing and security review.

This document records package metadata and upstream documentation for engineering review; it is not legal advice.
